# Pomogaika — записка к передаче кода

Архив собран 12.10.2026. Это полный код проекта, но **без секретов и без данных**.

## Чего в архиве намеренно нет

| Что | Почему |
|---|---|
| `.env` | токен Telegram-бота, пароль почтового ящика, ключ модели. Шаблон — в `.env.example` |
| `data/` и любые `*.db` | рабочая база: имена гостей, даты, брони. Персональные данные |
| `dialogs/` | 87 скриншотов реальных переписок с гостями |
| `.venv/`, `__pycache__/` | окружение, ставится из `requirements.txt` |
| адрес прод-сервера | заменён на `<SERVER_IP>` в `docs/deploy.md` и `deploy/upload.ps1` |

База создаётся с нуля при первом запуске, демо-объект засевается из `ops/kava/` —
то есть проект поднимается без наших данных.

## Как запустить локально

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env     # заполнить TELEGRAM_BOT_TOKEN своим тестовым ботом
.\run.ps1                  # uvicorn на 127.0.0.1:8000
```

Тесты: `.\.venv\Scripts\python.exe -m pytest` — должно быть 101 passed.

Важно: `run.ps1` поднимает ещё и Telegram-бота long-polling'ом в том же процессе.
С одним и тем же токеном нельзя запускать его локально и на сервере одновременно —
обе стороны получат `TelegramConflictError`. Для локальной работы нужен свой бот.

Вход в мини-апп закрыт подписью Telegram: для локальной отладки ручек поставь
`TELEGRAM_AUTH_REQUIRED=false` в `.env`. На сервере так делать нельзя.

## Что стоит знать до правок

- Интерфейс мини-аппа — один файл `app.html`. Правки поиск-заменой по нему уже
  один раз снесли пять функций разом; перед выкаткой гонять `node tools/render_check.js`.
- Площадки отдают занятость зеркально друг другу: совпадающие брони — не овербукинг.
  Правило одно и живёт в `services/stay.py`.
- Сейчас система рассчитана на **один объект**: `session.query(Property).one()`
  стоит примерно в 20 местах. На втором объекте упадёт — это известный долг.
