# WhatsApp рядом с Telegram

Гость по-прежнему пишет человеку, а не боту. Собственник в карточке брони выбирает, куда вести этот переход: в личный Telegram или в личный WhatsApp. Код брони один. Ответ собирает тот же черновик, что и для Telegram.

## Два адреса, один код

Кнопки в карточке брони:

- **Ссылка в Telegram** — `https://t.me/<username>?text=Здравствуйте!%20Бронь%20KAVA-7f3a`
- **Ссылка в WhatsApp** — `https://wa.me/<номер>?text=Здравствуйте!%20Бронь%20KAVA-7f3a`

`<username>` берётся из `TELEGRAM_OWNER_USERNAME`. `<номер>` — из `WHATSAPP_OWNER_PHONE`, только цифры, без плюса. Это номер, который привязан в WhatsApp Web, а не номер гостя.

Повторное нажатие не создаёт новый код. **Отозвать ссылку** гасит код сразу для обоих каналов. Срок тот же, что у Telegram: выезд плюс сутки.

Гость открывает чат с уже подставленным текстом и нажимает «Отправить». В адресе нет номера брони с площадки, только короткий код вроде `KAVA-7f3a`.

Пока гость ничего не отправил, в карточке две кнопки. После первого сообщения в канале вместо его кнопки появляется «Гость в Telegram» или «Гость в WhatsApp». Второй канал при этом не прячется.

## Что происходит с сообщением

WhatsApp не вызывает модель сам. Локальный процесс принимает текст и отдаёт его Помогайке на `POST /api/whatsapp/message`. Дальше тот же путь, что у лички Telegram:

1. В тексте ищется код брони.
2. Код забирает первый аккаунт, который его отправил. Второй номер или другой мессенджер по этому коду бронь не получает. Тот же человек может писать снова.
3. Чат WhatsApp записывается отдельно и не затирает телеграмный чат. Ответ уходит в канал, где гость написал в последний раз.
4. Первое сообщение «Здравствуйте! Бронь …» не идёт в модель: это приветствие по ссылке.
5. Остальной текст разбирает копайлот: свой ответ объекта, FAQ, модель, политика. Деньги, скидка и возврат по-прежнему без обещания. Код двери сам не выдаётся.

Группы, статусы, голос и фото до модели не доходят. Свои исходящие новым вопросом гостя не считаются. Сообщения, которые уже были в чате до запуска процесса, пропускаются.

Ручка WhatsApp принимает запрос только с этой машины (`127.0.0.1`). Снаружи она закрыта той же проверкой входа, что и остальные `/api/`.

## Два режима отправки

Режим хранит процесс WhatsApp, не Помогайка. Переключение — в терминале PowerShell, не в чате и не в Chrome:

```powershell
# модель отвечает сама
$json = '{"mode":"auto"}'
Invoke-RestMethod -Uri http://127.0.0.1:8792/mode -Method Post -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($json))

# только после разрешения
$json = '{"mode":"approve"}'
Invoke-RestMethod -Uri http://127.0.0.1:8792/mode -Method Post -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($json))
```

Текущий режим виден в `Invoke-RestMethod http://127.0.0.1:8792/health`, поле `mode`. Выбор сохраняется в `tools/whatsapp-web/logs/mode.json` и переживает перезапуск. По умолчанию `approve`.

- **approve.** Черновик появляется в очереди Помогайки и, если бот запущен, приходит собственнику в Telegram с кнопкой «Отправить». В WhatsApp тишина, пока кнопку не нажмут в мини-приложении или в боте. Приветствие по ссылке тоже ждёт эту кнопку.
- **auto.** Помогайка сразу просит локальный процесс отправить черновик. В очередь он не попадает.

Кнопка «Отправить» смотрит на канал черновика. Для WhatsApp она вызывает `http://127.0.0.1:8792/send`, а не Telegram Bot API. Если процесс WhatsApp лежит, статус черновика не меняется и в интерфейсе видна ошибка. Ссылку при этом скопировать можно.

Напоминания по пути гостя (до заезда, после заезда, перед выездом) и код калитки идут в тот же последний канал.

## Как запустить

Нужны два процесса. Сначала Помогайка, потом WhatsApp: иначе входящее некуда записать.

```powershell
.\run.ps1
```

```powershell
cd tools\whatsapp-web
npm install
npm start
```

Первый запуск показывает QR. Телефон → Связанные устройства → Привязка устройства. Сессия лежит в `tools/whatsapp-web/session/` и в git не входит. Второй `npm start`, пока первый ещё жив, не запускать: это два клиента на один номер.

Окно Chrome закрывать не нужно. Лог событий — `tools/whatsapp-web/logs/whatsapp.jsonl`. Туда же не коммитить: там тексты переписок.

В `.env`:

```
TELEGRAM_OWNER_USERNAME=username_без_собаки
WHATSAPP_OWNER_PHONE=79XXXXXXXXX
```

Пустой username ломает только кнопку Telegram. Пустой номер ломает только кнопку WhatsApp.

`tools/whatsapp-web/draft.py` — отдельная проверка модели без WhatsApp: на stdin JSON `{"text":"..."}`, на stdout черновик. Боевой путь его не вызывает.
