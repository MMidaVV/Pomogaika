# Max рядом с Telegram и WhatsApp

Это локальный эксперимент, как WhatsApp: личный аккаунт Max через Node-Max. Это не официальный бот MAX и не часть боевого канала.

Гость пишет человеку, а не боту. В карточке брони собственник выбирает, куда вести переход: Telegram, WhatsApp или Max. Код брони один. Ответ собирает тот же черновик, что и для Telegram.

## Три адреса, один код

Кнопки в карточке брони:

- **Ссылка в Telegram** — `https://t.me/<username>?text=Здравствуйте!%20Бронь%20KAVA-7f3a`
- **Ссылка в WhatsApp** — `https://wa.me/<номер>?text=Здравствуйте!%20Бронь%20KAVA-7f3a`
- **Ссылка в Max** — `https://max.ru/u/…`, профиль из `MAX_OWNER_LINK`

У личного профиля Max нет параметра, который подставляет текст в конкретный чат. Адрес `https://max.ru/:share?text=` открывает выбор любого чата, поэтому ссылкой гостя он не служит. Фраза `Здравствуйте! Бронь KAVA-7f3a` лежит в тексте, который копируется вместе со ссылкой. Гость открывает ваш профиль и отправляет эту фразу сам.

Повторное нажатие не создаёт новый код. **Отозвать ссылку** гасит код сразу для всех каналов. Срок тот же: выезд плюс сутки.

Пока гость ничего не отправил, в карточке три кнопки. После первого сообщения в канале вместо его кнопки появляется «Гость в Max». Остальные каналы при этом не прячутся.

## Что происходит с сообщением

Max не вызывает модель сам. Локальный процесс принимает текст и отдаёт его Помогайке на `POST /api/max/message`. Дальше тот же путь, что у лички Telegram:

1. В тексте ищется код брони.
2. Код забирает первый аккаунт, который его отправил. Второй чат или другой мессенджер по этому коду бронь не получает. Тот же человек может писать снова.
3. Чат Max записывается отдельно и не затирает Telegram и WhatsApp. Ответ, напоминание и код двери уходят в канал, где гость написал в последний раз.
4. Первое сообщение «Здравствуйте! Бронь …» не идёт в модель: это приветствие по ссылке.
5. Остальной текст разбирает копайлот. Деньги, скидка и возврат по-прежнему без обещания. Код двери сам не выдаётся.

Группы, каналы, служебное «Новый вход» и сообщения без текста до модели не доходят. Свои исходящие новым вопросом гостя не считаются. Сообщения, которые уже были в чате до запуска процесса, пропускаются.

Ручка Max принимает запрос только с этой машины (`127.0.0.1`). Снаружи она закрыта той же проверкой входа, что и остальные `/api/`.

## Два режима отправки

Режим хранит процесс Max, не Помогайка. По умолчанию `approve`. Переключение — в терминале PowerShell:

```powershell
# модель отвечает сама
$json = '{"mode":"auto"}'
Invoke-RestMethod -Uri http://127.0.0.1:8793/mode -Method Post -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($json))

# только после разрешения
$json = '{"mode":"approve"}'
Invoke-RestMethod -Uri http://127.0.0.1:8793/mode -Method Post -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($json))
```

Текущий режим виден в `Invoke-RestMethod http://127.0.0.1:8793/health`, поле `mode`. Выбор сохраняется в `tools/max-web/logs/mode.json` и переживает перезапуск.

- **approve.** Черновик появляется в очереди Помогайки и, если бот запущен, приходит собственнику в Telegram с кнопкой «Отправить». В Max тишина, пока кнопку не нажмут в мини-приложении или в боте. Приветствие по ссылке тоже ждёт эту кнопку.
- **auto.** Помогайка сразу просит локальный процесс отправить черновик.

Кнопка «Отправить» для канала Max вызывает `http://127.0.0.1:8793/send`. Если процесс Max лежит, статус черновика не меняется и в интерфейсе видна ошибка.

## Как запустить

Нужны два процесса. Сначала Помогайка, потом Max: иначе входящее некуда записать.

```powershell
.\run.ps1
```

```powershell
cd tools\max-web
npm install
npm start
```

Первый запуск показывает QR в терминале. Его подтверждает приложение Max на телефоне: Профиль → Устройства → Войти по QR-коду. Веб-версия и десктоп этот QR не принимают. Если на аккаунте стоит пароль входа, его спрашивает тот же терминал; пароль на диск не пишется.

Сессия лежит в `tools/max-web/session/` и в git не входит. Второй `npm start`, пока первый ещё жив, не запускать: порт `8793` занят.

Лог событий — `tools/max-web/logs/max.jsonl`. Туда же не коммитить: там тексты переписок.

В `.env`:

```
MAX_OWNER_LINK=https://max.ru/u/…
```

Ссылку берут в профиле Max. Пустая или чужая (группа, `:share`) ломает только кнопку Max.

`tools/max-web/draft.py` — отдельная проверка модели без Max: на stdin JSON `{"text":"..."}`, на stdout черновик. Боевой путь его не вызывает.
