# Витрины и цена

Черновик v0.1. Слой объявлений на площадках (выйти, выбрать, держать в порядке) и слой управления ценой. Не MVP, первичное понимание для планирования.

Общее ограничение для обоих слоёв: контент и цены можно отдавать на площадки только там, где есть API или channel-менеджер. Через iCal не передаётся ни описание, ни цена. Поэтому оба слоя стоят после календарного (см. [architecture.md](architecture.md), слой броней) и зависят от его возможностей.

## 1. Витрины

### 1.1 Обещание продукта

Формулировка для собственника: «Сейчас вы только на Авито. С Pomogaika ваш объект стоит на всех площадках, где его ищут, с одним календарём и одной перепиской, а вы видите, откуда приходят деньги».

Что в этом честно, а что нет:

| Честно | Нечестно |
|---|---|
| Один календарь, одна переписка, одна цена на всех витринах | «Плюс десять витрин равно в разы больше броней». Спрос не складывается: Авито и Суточно закрывают большую часть посуточного спроса на побережье, Яндекс добавляет заметно, остальные дают проценты |
| Десять витрин как число достижимо, если считать витрины агрегаторов | Публикация под нашим аккаунтом без агентских отношений. Площадки заключают договор с собственником и платят ему |
| Прирост броней по источникам виден в отчёте | Витрины ради витрин: каждая добавляет риск пересечения броней и ещё один чат, куда пишут гости |

Обещать стоит результат (брони по источникам), витрины как средство.

### 1.2 Откуда берутся витрины

| Группа | Что это | Что нужно |
|---|---|---|
| Площадки напрямую | Авито, Суточно, Яндекс Путешествия, Островок, Твил, 101Hotels, Броневик (командировочные) | Аккаунт собственника на каждой: регистрация, паспорт, у Островка видеоверификация. 20–40 минут на площадку, мы ведём за руку |
| Витрины через агрегатор | Островок поставляет инвентарь партнёрским витринам (Ozon Travel, Т-Банк Путешествия, МТС Travel, Сбер Путешествия и другие). Актуальный список проверять у Островка | Одно подключение даёт несколько витрин. Честный способ дойти до «десяти» |
| Своя витрина | Сайт объекта с модулем бронирования и оплатой, карточки в Яндекс Бизнесе и 2ГИС, канал в Telegram | Делаем мы. Сюда идут повторные гости без комиссии площадок |

Итого реально: 5–7 площадок напрямую, 4–6 витрин через агрегаторов, одна своя.

### 1.3 Площадки: чем отличаются

Цифры с сайтов площадок и обзоров на осень 2026, проверять перед решением.

| Площадка | Комиссия и модель | Аудитория | Интеграция |
|---|---|---|---|
| Авито | Онлайн-бронирование обязательно, около 15% с оплаченных броней, без платы за размещение | Самая массовая, много запросов, чувствительна к скорости ответа | Партнёрский API, автозагрузка по XML-фиду для профи-аккаунтов |
| Суточно.ру | Сервисный сбор 15–25% с гостя, вознаграждение сервиса удерживается из предоплаты и компенсируется собственнику бонусами | Целевая посуточная, семьи и отпускники | iCal, API только для channel-менеджеров |
| Яндекс Путешествия | 17% с февраля 2026 | Растущая, городские и командировочные, трафик из Яндекса | Через channel-менеджеры, прямой API партнёрам |
| Островок | Стандартно 15%, открыт для физлиц с видеоверификацией | Отельная, командировочные, корпоративные | Через channel-менеджеры |
| Твил | По обзорам до 30% | Внутренний туризм, курортные регионы | iCal |
| Своя витрина | 0%, эквайринг | Повторные гости, прямой поиск | Наш модуль бронирования |

### 1.4 Правила выбора площадок

Три вопроса на каждую площадку:

1. Даёт ли она приростные брони, а не те же, что уже приходят через Авито.
2. Сколько стоит бронь с учётом комиссии, предоплаты и штрафов за отмену хостом.
3. Можно ли синхронизировать календарь без ручной работы.

Для побережья: первый круг Авито и Суточно, второй Яндекс, третий Островок для межсезонья и командировочных. Каждая новая площадка включается как эксперимент на 4–6 недель с атрибуцией броней по источнику. Не даёт броней, отключается, чтобы не держать лишний риск пересечений.

### 1.5 Что влияет на ранжирование и что здесь делает продукт

| Фактор | Что делает продукт |
|---|---|
| Скорость ответа и доля подтверждений | Гостевой агент, уже в P0 |
| Полнота карточки и удобств | Модель проверяет карточку по чек-листу площадки и подсказывает незаполненное |
| Фото | Порядок и обложка, подсказки, чего не хватает (ванная, вид из окна) |
| Отзывы | Просьба об отзыве через сутки после выезда только у довольных гостей (по оценке через час после заезда), черновики ответов на отзывы |
| Отмены хостом | Не должно быть, задача календарного слоя |
| Цена относительно похожих | Слой цены, раздел 2 |

### 1.6 Мастер выхода на площадку

1. Диагностика при онбординге: где объект есть, где нет, оценка доли рынка недостающих площадок по городу (точная цифра появится при объёме объектов в городе).
2. Собственник выбирает площадку, система собирает пакет из базы знаний объекта под её формат: заголовок, описание, удобства, правила, порядок фото. Проверка по требованиям модерации.
3. Публикация: через API и фид (Авито), через channel-менеджер, или пошаговая инструкция с готовыми текстами для ручной публикации. Регистрация аккаунта всегда на собственнике.
4. Подключение к календарной синхронизации, эксперимент 4–6 недель, решение по цифрам.
5. Своя витрина делается сразу при онбординге: сайт объекта, Яндекс Бизнес, 2ГИС. Это витрина, которую не отберёт ни одна площадка.

### 1.7 Режим «наша витрина»

Многие помогайки размещают чужие квартиры под своим аккаунтом, это их главный крючок для собственника. У нас это возможный отдельный режим на этапе УК: объекты под нашим аккаунтом, деньги через нас, агентский договор, налоги и ответственность на нас. Не по умолчанию. По умолчанию аккаунты собственника, управление наше.

## 2. Цена

### 2.1 Принцип

Расчёт цены детерминированный и объяснимый: правила и данные, не LLM. Собственник должен доверять цифре и понимать, откуда она. LLM работает на границе: объясняет цену словами, переводит команды собственника в параметры, пишет еженедельную сводку с предложениями.

### 2.2 Слои формулы

Ежедневный расчёт на горизонт до года. Для каждой даты:

```
цена = база
     × сезон
     × день недели
     × горизонт брони
     × загрузка
     × события и погода
     × поправка на конкурентов
→ ограничить [пол, потолок]
→ округлить
→ надбавка под комиссию площадки
```

| Слой | Что учитывает | Откуда данные |
|---|---|---|
| База | Якорная цена объекта | Собственник при онбординге, потом история |
| Сезон | Высокий июнь–август, плечи май и сентябрь, низкий ноябрь–март, пики: Новый год, майские, длинные выходные | Календарь региона, своя история |
| День недели | Пятница и суббота дороже, воскресенье дешевле | История броней |
| Горизонт брони | За месяц полная цена, за неделю минус, за два дня ещё минус, в день заезда пол | Кривая из стратегии |
| Загрузка | Месяц вперёд заполнен выше цели: поднимать; ниже: снижать | Своя загрузка против цели |
| События и погода | Фестивали, праздники, прогноз на выходные: на побережье солнечные выходные дают всплеск last-minute | Календарь событий, прогноз |
| Конкуренты | Позиция относительно 5–10 похожих объектов рядом | Публичные цены в выдаче площадок: сначала вручную раз в неделю, автоматизация отдельно |
| Длина проживания | Скидка за неделю и месяц, минимальный срок по сезону, снятие минимума на «сироты-ночи» между бронями | Календарь |
| Пол и потолок | Пол = уборка + расходники + износ + минимальная маржа, ниже никогда. Потолок из конкурентов | Себестоимость оборота |
| Площадка | На площадке с высокой комиссией цена выше на разницу комиссий | Таблица площадок |

### 2.3 Стратегии как пресеты

Собственник выбирает словами. Пресет это набор параметров формулы.

| Стратегия | Что делает | Кому |
|---|---|---|
| Сдать любой ценой | Низкий пол, агрессивная last-minute кривая, минимальный срок 1 ночь, цель по загрузке 90%+ | Ипотека, межсезонье, новый объект без отзывов |
| Максимальный доход | Выше конкурентов, терпит пустые ночи, минимальный срок в сезон 3+, высокий пол | Сезон, объект с рейтингом |
| Спокойствие | Меньше оборотов: минимум 3–4 ночи, скидка за неделю, дорогие короткие заезды | Собственник, которому важнее меньше уборок |
| Как у соседей | Медиана комп-сета ±5% | Не хочет думать |
| Ручной с подсказками | Система предлагает, собственник подтверждает одной кнопкой | Все на старте, это наш копайлот |

Параметры пресета: пол (множитель к себестоимости), кривая горизонта, целевая загрузка по месяцам, правила минимального срока, позиция относительно комп-сета, допуск на изменение цены за день.

Команды собственника в чате переводятся в переопределения поверх пресета: «на майские не ниже шести тысяч», «неделю после Нового года сдать хоть как-то», «на выходные не трогай». Переопределения видны в объяснении цены.

### 2.4 Диагностика: просмотры, обращения, брони

У площадок есть статистика просмотров карточки и обращений. Матрица отделяет ценовые проблемы от контентных:

| Просмотры | Обращения | Брони | Диагноз |
|---|---|---|---|
| Мало | — | — | Карточка и ранжирование, не цена. Снижать бесполезно |
| Много | Мало | Нет | Цена высокая или отзывы плохие |
| Много | Много | Нет | Сомнения гостей: смотреть переписку, условия, предоплату |
| Много | Есть | Есть, но пусто в конкретные даты | Локальная проблема дат: минимальный срок, сироты-ночи, горизонт |

Матрица показывается собственнику в еженедельной сводке вместе с предложением.

### 2.5 Где здесь LLM

- Объяснение: «на 20–22 сентября соседи по 3 200, у вас пусто, предлагаю 2 900».
- Разбор команд собственника в параметры и переопределения.
- Еженедельная сводка: что изменилось, что предлагаем, одна кнопка «применить».
- Не в расчёте цены.

### 2.6 Данные и сетевой эффект

На одном объекте истории мало, эластичность не оценить. На 30–50 объектах в одном городе появляется общий сигнал спроса, конкуренты видны напрямую, календарь событий один. Это причина, почему полноценная цена отложена до объёма, и это преимущество платформы, которого нет у собственника-одиночки.

### 2.7 Риски

- Ценовые войны в маленьком городе, если все на «сдать любой ценой». Пол и потолок обязательны, «как у соседей» не должен становиться гонкой вниз.
- Лимиты площадок на частоту изменений цен и на минимальные цены.
- Мониторинг конкурентов через выдачу площадок это серая зона. Начинать с ручного ввода 5–10 объектов раз в неделю.
- Недоверие собственника к автоматической цене. Снимается объяснением каждой цены, полом и копайлотом по умолчанию.
- У Bnovo и RealtyCalendar есть модули умных цен. Наше отличие: объяснимость и управление через чат для тех, кто не сядет за панель.

## 3. Порядок внедрения

| Этап | Что делаем | Зависимость |
|---|---|---|
| С аналитикой P1 | Загрузка, средний чек, источники, просмотры где есть. Еженедельно в чат: «на следующие выходные пусто, предлагаю снизить до X, поставить?». Копайлот-цена без движка | Аналитика, канал собственника |
| Движок правил | Пять пресетов, пол и потолок, кривая горизонта, объяснение каждой цены, отдача цен через channel-менеджер и API Авито | Календарный слой с API |
| Витрины | Чек-лист карточки, порядок фото, отзывы через бота, мастер выхода на площадку, своя витрина | База знаний объекта, атрибуция броней по источнику |
| На объёме | Мониторинг конкурентов, события и погода, общая модель спроса по городу, цены по площадкам с разницей комиссий | 30–50 объектов в городе |

## 4. Что делать на пилоте

Одно действие: раз в неделю записывать просмотры и обращения по объявлениям вместе с ценами трёх-пяти соседей. Через сезон это единственные данные, по которым можно проверить, работают ли слои формулы для конкретного объекта.

## 5. Открытые вопросы

1. Режим «наша витрина» с агентским договором: делать ли вообще и когда.
2. Мониторинг конкурентов: ручной ввод, партнёрские данные channel-менеджеров или собственный сбор.
3. Своя витрина: свой модуль бронирования или модуль channel-менеджера с нашим оформлением.
4. Как считать прирост броней от новой площадки, чтобы не путать перетекание с приростом.
5. Атрибуция брони к источнику при iCal-синхронизации, где данных о брони нет.
