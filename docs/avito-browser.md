# Локальный Авито через браузер

Эксперимент на ветке `experiment/avito-browser`. Читает и отправляет сообщения **личного** аккаунта Авито через видимый Chrome. В Помогайке появляется карточка с черновиком модели. В Авито ничего не уходит, пока человек не нажмёт кнопку.

Это не продуктовый путь. Боевой Авито KaVa, почта, календари и Telegram-бот здесь не используются. Официальный Messenger API по-прежнему в плане, этот браузер его не заменяет.

Нужны Windows, Python 3.11+, Node.js 18+, установленный Chrome. Работает только на этой машине: браузер слушает `127.0.0.1`.

## Чего не делать

- Не раскомментировать в локальном `.env` строку `TELEGRAM_BOT_TOKEN`. Пока она задана, `run.ps1` забирает `getUpdates` у продакшена и вместе с ботом запускает почту и календари KaVa.
- Не раскомментировать `IMAP_*`. Поставить `ICAL_SYNC_MINUTES=0`. Старое значение `30` оставить закомментированным, не удалять.
- Не входить в аккаунт KaVa. Окно Chrome — личный аккаунт того, кто ведёт эксперимент.
- Не запускать второй `npm start`, пока первый ещё жив. Каждый запуск открывает Chrome заново и снова логинится. Аккаунт от этого страдает.
- Не нажимать «Отправить текст модели», не прочитав жёлтый пузырь. Модель отвечает как по объекту KaVa (адрес, просмотр), даже если в Авито пишут про тумбу или другую вещь.
- Не коммитить `tools/avito-browser/profile/`, `logs/` и `.env`. Там сессия, тексты переписок и ключи.

## Два процесса

1. Помогайка: http://127.0.0.1:8000
2. Браузер Авито: http://127.0.0.1:8791 (`/send` и `/thread`). Его вызывает только Помогайка, когда человек открыл чат или нажал «Отправить».

Сначала поднимается Помогайка, потом браузер. Иначе новое сообщение из Авито некуда записать, и скрипт повторит его на следующем опросе.

## 1. Помогайка

Из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env
```

В `.env` для этого эксперимента:

- `TELEGRAM_BOT_TOKEN` закомментировать. Значение не стирать.
- `IMAP_HOST`, `IMAP_PORT`, `IMAP_USER`, `IMAP_PASSWORD`, `IMAP_FOLDER`, `IMAP_POLL_MINUTES` закомментировать.
- `ICAL_SYNC_MINUTES=0`
- `TELEGRAM_AUTH_REQUIRED=false` — иначе страница `/app` не откроется без подписи Telegram.
- `TOKENROUTER_API_KEY` оставить, если нужен живой черновик. Модель `TOKENROUTER_MODEL`, по умолчанию `z-ai/glm-5.3-flash`. Без ключа черновик собирается из FAQ.

Запуск:

```powershell
.\run.ps1
```

В логе должно быть предупреждение, что `TELEGRAM_BOT_TOKEN` пуст и бот не запущен. Это правильное состояние. Строки про polling быть не должно.

Пустая база при первом старте засевается демо-объектом KaVa. Карточки Михаила и Дарьи и ответы в «Ответах гостям» — не из Авито.

Интерфейс: http://127.0.0.1:8000/app

Переписка Авито открывается кнопкой с облачком слева от оранжевого аватара. Пункт «Ответы гостям» — это FAQ, не чат.

## 2. Браузер

Отдельный терминал:

```powershell
cd tools\avito-browser
npm install
npm start
```

Откроется обычное окно Chrome с профилем `tools/avito-browser/profile/`. Профиль в git не входит: на новой машине вход делается заново. Логин и код из SMS вводит человек в этом окне. Скрипт ждёт сколько угодно и сам окно не закрывает.

Когда в терминале появится «Мессенджер открыт» и список диалогов, вход прошёл. Следующая строка: «Уже открытые диалоги в Помогайку не переношу». Старые чаты карточками не становятся. Карточка появляется только на сообщение, которое пришло после этого момента. Опрос списка — раз в 15 секунд.

Остановить: закрыть окно Chrome или Ctrl+C в терминале браузера. Не запускать новый `npm start`, пока старый процесс ещё держит окно.

## Как выглядит диалог в Помогайке

На одно объявление и одного собеседника — одна карточка, пока она в статусе ожидания.

- Слева белым — входящие.
- Справа синим — уже отправленное, с подписью «вы».
- Жёлтый пузырь — предложение модели. Оно не отправлено.

Кнопки:

- «Отправить текст модели» — уходит жёлтый текст.
- Поле «Свой текст, не от модели» и «Отправить свой» — уходит то, что набрано. Enter тоже отправляет.

После отправки карточка остаётся в списке: модель можно поправить и отправить ещё раз. «Отвечу сама» для Авито скрыта и ничего не шлёт.

Открытие карточки один раз перечитывает живую переписку из уже открытого Chrome. Новое окно при этом не создаётся.

Если вместо отправки всплывает «браузер Авито не запущен», не работает процесс на порту 8791. Если «этот чат не виден в списке Авито», окно не на странице мессенджера или сессия слетела на форму входа.

## Что трогать в коде

| Задача | Файл |
|---|---|
| Окно Chrome, список диалогов, отправка, чтение переписки | `tools/avito-browser/watch.mjs` |
| Вызов браузера из Python | `src/pomogaika/platforms/avito_local.py` |
| Карточка, тред, запрет автоотправки | `src/pomogaika/services/drafts.py` |
| Ручки `/api/avito/message`, `/api/avito/thread/{id}`, отправка | `src/pomogaika/web/app.py` |
| Пузыри и кнопки | `src/pomogaika/web/static/app.html` |

`app.html` сервер читает с диска при каждом запросе. Обновления страницы достаточно. Правки Python и `watch.mjs` видны только после перезапуска своего процесса. Браузер перезапускать только когда без этого нельзя прочитать новый код, и только один раз.

Проверка карточки без живого Авито:

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -m pytest tests/test_core.py::test_avito_draft_stays_until_send -q
```
